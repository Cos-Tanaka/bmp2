1. BPMとは

BPM（進捗監視盤）は、Backlog の案件（親課題）と子課題の情報をもとに、予定工数・実績工数の対比、進捗率、健全性をリアルタイムに可視化するダッシュボードです。工数超過や期限遅れの早期検知を目的としています。

  • データは Backlog から自動取得され、約60秒ごとに更新されます（手動更新も可）。
  • 画面は案件（親課題）単位で一覧表示され、各案件を開くと子課題が展開されます。
  • 右上のボタンからガントチャート、実施工数確認画面、本ガイド、テーマ（ダーク/ライト）切替を開けます。

  1. 1サマリーカード：案件数・予定/実績工数の合計・予実差・健全性の内訳を一目で把握できます。
  2. 2案件 / 課題：先頭の ▶ をクリックすると子課題が展開されます。グレーの行が親案件、白い行が子課題です。
  3. 3進捗バー：親行は「予（予定の経過）／実（実績の消化率）」の2本、子行は実績1本。実績が予定を大きく超えると黄→赤に変化します。
  4. 4健全性：🟢正常／🟡注意（期限間近 or 実績が予定超過）／🔴危険（期限超過 or 実績が予定の120%超）。
  5. 5残工数：残りの想定工数。予実差に応じて色が変わります（超過=赤、要注意=黄、余裕=青/緑）。親行は人月、子行は時間で表示。
  6. 6kintoneアイコン：案件に Kintone番号がある場合のみ表示。クリックで該当の kintone レコードを新しいタブで開きます（番号が無い案件には表示されません）。
  7. 7実績工数（点線下線）：子課題の実績工数はクリックでき、実績工数の入力レイヤーが開きます（→ 5章）。
  8. 8📊 実施工数確認：実績工数の入力履歴を検索・集計する画面を新しいウィンドウで開きます（→ 6章）。
ヒント：各課題番号（V2A9-xxxx）をクリックすると Backlog の課題ページが新しいタブで開きます。

3. フィルターで絞り込む

監視テーブルは複数の条件で絞り込めます。設定したフィルターはブラウザに保存され、次回開いたときも維持されます。

ステータス すべて概算見積基本設計正式見積開発中テストリリース済み本番リリース済み
  • 健全性：🟢/🟡/🔴 で案件を絞り込みます。
  • 状態：対応中／完了の切り替え（もう一度押すと解除）。
  • 担当者：親案件の担当者で絞り込み。
  • 子課題ソート：展開した子課題の並び順（担当者→期間／期間→担当者）。
  • 1 表示（全て開く／全て閉じる）：すべての案件の子課題を一括で展開／折りたたみます。担当者で絞り込むと該当案件が自動展開されるため、案件数が多いときは 「▶ 全て閉じる」 でまとめて畳むと見やすくなります。
  • ステータス：案件のフェーズ（概算見積〜本番リリース済み）で絞り込み。
保存される条件：健全性・状態・担当者・ステータス・子課題ソートのすべて。リロードしても直前の絞り込みが復元されます。

4. 子課題の詳細を見る・編集する

子課題の案件名（タイトル）をクリックすると、詳細レイヤーが画面内に開きます。ここでは 担当者・開始日・期限日・進捗率・チェック状態を変更でき、保存すると Backlog に反映されます。また、この画面内で実績工数を直接入力することもできます（→ 5章と同じ入力欄）。

  2. 2開始日 / 期限日：日付ピッカーで変更します。「開始日 > 期限日」の場合は保存時にエラーになります。
  3. 3進捗率 / チェック状態：プルダウンから選択します（Backlog の選択肢と同じ）。

閉じる：右上の ✕、背景クリック、または Esc キーで閉じられます。

5. 実績工数を日々入力する

子課題の実績工数（点線下線のセル）をクリックすると、実績工数の入力レイヤーが開きます。日々の作業時間をここから加算していきます。同じ入力欄は、案件名クリックで開く詳細レイヤー（→ 4章）の中にも組み込まれているため、担当者や進捗率の変更とあわせて一度に入力することもできます。

  1. 1追加工数 (h)：今回加算する時間（数値のみ・必須）。例: 1.5。
  2. 2名前：入力者名（必須）。一度入力するとブラウザに保存され、次回以降は自動入力されます。
  3. 3日時：入力を記録する日時（必須）。レイヤーを開いた時点の現在日時が初期値として入りますが、過去の作業を後からまとめて入力する場合などは自由に変更できます。ここで指定した日時が入力履歴と「実施工数確認」画面の集計日になります。
  4. 4追加：押すと ①Backlog の実績工数に加算 ②入力履歴（後述）に記録、の両方が行われます。
  5. 5入力履歴：この子課題への過去の入力（名前・日時・追加工数）が新しい順に表示されます。
  6. 6🗑 削除：その履歴を削除します。クリックすると確認ダイアログが表示され、実行すると ①入力履歴から削除 ②Backlog の実績工数からその分を減算、が行われます（減算結果がマイナスになる場合は 0 になります）。
バリデーション：追加工数・名前・日時はいずれも必須です。追加工数は数値のみ（0 より大きい値）を受け付けます。
削除について：削除しても記録自体はデータベース上に残る論理削除のため、一覧・集計からは除外されますが、後から追跡は可能です。実績工数の減算は 0 未満にはならず 0 で止まります。

6. 実施工数確認画面の使い方

ヘッダーの 「📊 実施工数確認」 から新しいウィンドウで開きます。入力された実績工数を 名前 と 検索日 で検索し、親案件・名前・追加日ごとに集計して時間で表示します。

  2. 2検索日：単一日付で絞り込みます（その日に追加された分のみ）。

集計単位：同じ親案件・同じ名前・同じ日であれば、複数の子課題への入力も1行にまとめて集計されます。

7. ガントチャートで期間を俯瞰する

ヘッダーの 「📅 ガント」 から、案件・子課題の期間をタイムライン上のバーで俯瞰できる画面を開けます。一覧画面と同じデータ（同じ約60秒ごとの自動更新）を使い、「📋 案件別」（親案件ごとの階層表示）と「👤 担当者別」（担当者ごとに子課題だけを並べる表示）を切り替えられます。

  1. 1粒度（日／週／月）：時間軸の目盛りの細かさを切り替えます。「📍 今日へ」で今日の位置まで自動スクロールします。
  2. 2日付なしを隠す：開始日・期限日のどちらかが未設定でバーを描けない案件・課題を非表示にします（既定でON）。チップの数字は非表示中の件数です。オフにすると全件表示されますが、バーの無い行が増えます。
  3. 3集約バー（細いバー）：親案件自身に開始日・期限日が設定されていない場合、子課題の中の最も早い開始日〜最も遅い期限日から自動計算した期間を細いバーで表示します（Backlog では親案件に日付を入れない運用が多いため）。
  4. 4進捗の塗り／予定ライン：バー内の塗りが進捗率（子課題は進捗率フィールド、無ければ実績/予定工数の比率）。縦の白線は「今日時点で本来あるべき進捗（期間に対する経過割合）」の位置です。塗りが白線より左なら遅れ気味、右なら順調です。
  • 色分け：バーの色は健全性と同じ基準です（🟢正常／🟡注意／🔴危険）。
  • 今日ライン：縦の青い線が今日の日付です。
  • 階層表示：左側の ▶ で子課題の開閉、「全て開く／全て閉じる」で一括操作できます（一覧画面と同じ）。
  • フィルター：健全性・状態・担当者・ステータスは一覧画面と共通で、設定内容もブラウザに保存され両画面で共有されます。
  • バーや課題番号のクリック：該当の課題を Backlog の新しいタブで開きます。バーにマウスを乗せると、期間・工数・進捗などの詳細がツールチップで表示されます。
  • 子課題の詳細を編集する：子課題のタイトル（点線下線）をクリックすると、一覧画面と同じ詳細レイヤー（→ 4章）が開き、担当者・進捗率・日程・実績工数をその場で編集できます。バー自体をドラッグして日程を変えることはできません。

担当者別ビューで個人のスケジュールを見る

「👤 担当者別」ビューに切り替えると、親案件の行は表示されず、担当者ごとに子課題だけがグルーピングされて並びます。誰にどれだけタスクが割り当たっているか、期間に空きがないかを一人ずつ確認できます。

http://localhost:3031/gantt.html

6/226/297/67/137/20
▶ 👤 佐藤 2
V2A9-1706[V2A9-1652]出力バッチの実装
▶ 👤 未割当 3
  1. 5ビュー切替：「📋 案件別」（従来どおり）と「👤 担当者別」を切り替えます。担当者別ビューでは親案件行は出ず、子課題のタイトル横に [V2A9-1652] のように親案件のキーが小さく表示されます。
  2. 6担当者の複数選択：担当者別ビューでは、担当者を複数チェックして絞り込めます（例：自分のチームのメンバーだけ表示）。選択状態はブラウザに保存され、次回も同じメンバーで表示されます。「未割当」グループは一番下に固定表示されます。
  • グループの開閉：担当者名の左の ▶ で開閉できます。「全て開く／全て閉じる」も担当者単位で効きます。
  • グループヘッダの表示：担当者名の横に、表示中の子課題数と予定/実績工数の合計（計 ○h/○h）が表示されます。
  • 空きの見つけ方：一人の担当者の行を縦に見て、バーが途切れている期間が空きです。タスクが1件も無い担当者はグループ自体が表示されません（プロジェクトに無関係な参加者も多く登録されているため、あえて0件表示はしていません）。
  • フィルターの引き継ぎ：健全性・状態・「処理済み・完了を隠す」・ステータス・粒度・日付なしを隠す、は案件別ビューと共通の設定がそのまま適用されます（ステータスは子課題の親案件のフェーズで判定します）。
