# 実装指示書：ガントチャート 担当者別ビュー + 子課題詳細モーダル共通化

この指示書は、確定済みの「改修計画書_担当者別ガント.md」「質問票_担当者別ガント.md」（同じ `docs/` 内）を実装に落としたものです。仕様判断はすべて確定済みのため、**この指示書の記載どおりに実装してください**。判断に迷う点が出た場合は、勝手に仕様を決めず作業を止めて質問してください。

## 0. 前提知識（必読）

- このプロジェクトはビルド工程なし・フレームワークなしの素の HTML/JS です。`frontend/html/index.html`（一覧）と `frontend/html/gantt.html`（ガント）はそれぞれ単一ファイルで、全 JS がインラインです。
- `frontend/html` は bind mount されているため、フロント変更の反映は `docker compose restart frontend` のみ。**バックエンド（`backend/app.py`）は一切変更しません。**
- `/api/issues` のレスポンス: 親の配列。親 = `{id, title, assignee, start, due, plannedH, actualH, remainingH, health, status, statusId, customStatus, url, kintoneUrl, children}`。子 = `{id, title, assignee, assigneeId, start, due, plannedH, actualH, remainingH, progress, status, statusId, checkStatus, issueType, url}`。
  - 子の `assigneeId` は Backlog ユーザー ID（数値）、未割当は `null`。`assignee` は名前で、未割当時は文字列 `"未割当"` が入る（null ではない）。親には `assigneeId` が無いが、担当者別ビューは子のみ扱うため問題ない。
- その他の既存 API: `/api/project-users` → `[{id, name}]`、`/api/field-options` → 進捗率・チェック状態の選択肢、`PATCH /api/issue/<key>`、`GET|POST /api/worklog/<key>`、`DELETE /api/worklog/entry/<id>`。すべて既存のまま使う。
- localStorage: `bpm2-filter`（filter オブジェクト、**index.html と共有。スキーマを変更しない**）、`bpm2-gantt-scale`、`bpm2-gantt-hide-undated`、`bpm2-theme`。
- gantt.html の主要関数: `fetchData` / `visibleRows` / `resolveRange` / `buildAxis` / `renderGantt` / `barCell` / `childHealth` / `sortChildren` / `findItem` / ツールチップ系（`showTip` 等）/ フィルタ操作系。
- Backlog 組み込みステータス: `DONE_STATUS_IDS = [3, 4]`、`isDoneStatus(x)` は両ページに存在。

## 2. フェーズ1: 子課題モーダルの共通ファイル化（index.html リファクタ）

### 2.1 抽出対象（index.html 内）

- **HTML**: `<div class="modal-overlay" id="childModal">…</div>` のブロック全体（内部の `'dw'` プレフィックスの worklog パネル含む）。
- **CSS**: `.modal-overlay` / `.modal` / `.modal-head` / `.modal-body` / `.modal-foot` / `.modal-close` / `@keyframes modalIn` と、childModal 内部でのみ使うクラス（`.m-key` `.m-title` `.m-select` など。**grep で使用箇所を確認し、childModal と worklogModal の両方で使われているクラスは共有 CSS 側へ移す**）。
- **JS**: `openChildModal` / `closeChildModal` / `saveChildEdits` / `refreshChildModalHours` / `assigneeOptionsHTML` / worklog パネル共通系のうちモーダルから使う一式（`mountWorklogPanel` / `loadWorklogHistory` / `addWorklog` / `deleteWorklog` / `setWorklogMsg` / `worklogTargetId`）/ 状態変数 `modalChildId` `modalOriginal` / `/api/field-options`・`/api/project-users` の取得処理。

**注意**: `id="worklogModal"`（`'w'` プレフィックスの単独実績モーダル、一覧の実績セルから開く）は **index.html に残す**。ただし worklog 共通関数（`mountWorklogPanel` 等）は `'w'` からも呼ばれるため、共有 JS 側に置き、index.html からも参照する。`worklogTargetId` は `'w'` のとき index.html 側の `worklogChildId` を参照する必要があるため、下記 2.2 の init オプションで解決する。

### 2.2 child-modal.js の構造

グローバル汚染を避けるため、次の公開 API を持つ 1 オブジェクトにまとめる:

```js
// 利用側（各ページ）が起動時に呼ぶ
ChildModal.init({
  // 子課題IDから {child, parent} を返す（見つからなければ null）
  findChild: (childId) => { ... },
  // 保存・実績追加/削除が成功した後に呼ばれる（各ページで再描画/再取得する）
  onDataChanged: () => { ... },
  // 'w' プレフィックスの worklog 対象ID解決（index.html のみ渡す。省略可）
  getStandaloneWorklogId: () => worklogChildId,
});
ChildModal.open(childId);   // モーダルを開く（従来の openChildModal 相当）
```

- `init` 時にモーダルの HTML 文字列を `document.body` へ注入する（各ページの HTML には childModal を書かない）。
- `init` 時に `/api/field-options` と `/api/project-users` を fetch して内部変数に保持する（従来 index.html がやっていた処理を移す。失敗時は従来同様のフォールバック: 担当者は読み取り専用テキスト表示）。
- 既存のグローバル関数名（`openChildModal` 等）を HTML の `onclick` 属性が参照しているため、`window.openChildModal = (id) => ChildModal.open(id);` のような**互換エイリアスを child-modal.js 内で定義**し、既存の onclick 記述を書き換えずに済ませてよい。ただし注入する HTML 内の onclick からの参照も含めて漏れがないか確認すること。
- `escHtml` / `escAttr` は両ページに存在するが、child-modal.js は自前のローカルコピーを持つ（ページ側の定義に依存しない）。
- **ロジックは 1 行たりとも変えない**こと。移動のみ。保存後の一覧再描画（従来 `renderTable()` 等を直接呼んでいた箇所）だけは `onDataChanged()` 呼び出しに置換する。

### 2.3 index.html 側の変更

- `<head>` に `<link rel="stylesheet" href="child-modal.css">`、`</body>` 直前（既存インライン `<script>` より**前**）に `<script src="child-modal.js"></script>` を追加。
- 抽出した HTML / CSS / JS を削除し、起動処理で `ChildModal.init({...})` を呼ぶ。`findChild` は既存の子課題検索、`onDataChanged` は従来保存成功後にやっていた処理（`fetchData` / `renderTable` 相当）をそのまま渡す。
- `openChildModal('...')` を呼んでいる既存の onclick（子課題タイトル）はエイリアスで動くため変更不要。

### 2.4 フェーズ1 の完了条件

index.html の全モーダル操作が改修前と**完全に同一**に動くこと:
子課題モーダルで担当者・進捗・開始/期限日・チェック状態を保存 → 一覧に反映。`'dw'` パネルで実績追加/削除 → `refreshChildModalHours` により編集中の入力を消さずに 予定/実績/差分/残工数 のみ更新。単独 worklog モーダル（`'w'`）も従来どおり。ブラウザの開発者コンソールにエラーが出ないこと。

## 3. フェーズ2: gantt.html — 表示モード切替と担当者別ビュー

### 3.1 状態と永続化

```js
let viewMode = 'project';            // 'project' | 'assignee'
const MODE_KEY = 'bpm2-gantt-mode';
let selectedAssignees = [];          // 複数選択フィルタ。空配列 = 全員表示
const ASSIGNEE_MULTI_KEY = 'bpm2-gantt-assignees';
let collapsedGroups = new Set();     // 担当者別ビューで「閉じた」グループのキー（既定は全開）
```

- `selectedAssignees` の要素は **`assigneeId` の数値**、未割当は文字列 `"unassigned"`。保存・復元は `loadFilter` / 各操作時に localStorage へ JSON で読み書き（既存キーの読み書きと同じ try-catch スタイル）。
- **`bpm2-filter`（共有 filter オブジェクト）には新キーを追加しない。`filter.assignee`（単一選択・index.html と共有）には書き込まない。**
- グループのキーは `'a:' + (assigneeId ?? 'unassigned')` とし、`expanded`（親案件 ID の Set）とは別の `collapsedGroups` で管理する（案件別は「既定閉・開いたものを記録」、担当者別は「既定開・閉じたものを記録」で反転しているため Set を分ける）。`collapsedGroups` は永続化しない（現行 `expanded` と同様セッション限り）。

### 3.2 モード切替 UI

2 段目の filter-bar（粒度チップの並び）の先頭に追加:

```html
<span class="filter-label">ビュー</span>
<button class="chip" data-mode="project">📋 案件別</button>
<button class="chip" data-mode="assignee">👤 担当者別</button>
<div class="filter-sep"></div>
```

- クリックで `viewMode` を切替え、localStorage 保存、`applyFilterUI()`（active 反映）、`renderGantt()`、`scrollToToday()`。
- 担当者別モードのとき: 1 段目の既存単一選択 `<select id="assigneeFilter">`（とそのラベル）を `display:none` にし、代わりに複数選択 UI（3.4）を表示。案件別モードでは逆。切替時に表示を更新する関数を 1 つ作る（例 `updateModeUI()`）。
- 「▼ 全て開く / ▶ 全て閉じる」はモードに応じて `expanded` / `collapsedGroups` を操作する。

### 3.3 担当者別の行データ構築

`visibleRows()`（案件別・現行ロジック、**変更しない**）とは別に新設:

```js
/**
 * 担当者別ビューの行データ。
 * 全親の children をフラット化し、フィルタ適用後に assigneeId でグループ化して
 * [{ key, assigneeId, name, children: [...] }] を名前の五十音順（未割当は末尾）で返す。
 * children は各要素に parent への参照を付けて返す（左ペインの親キー表示・ツールチップ用）。
 */
function visibleAssigneeGroups() { ... }
```

フィルタ適用ルール（子課題単位で判定）:

| フィルタ | 判定 |
|---|---|
| 健全性 `filter.health` | `childHealth(c) !== filter.health` なら除外 |
| 状態 `filter.status` | `'done'` → `isDoneStatus(c)` のみ表示 / `'wip'` → `!isDoneStatus(c)` のみ表示 |
| `filter.hideDone` | `isDoneStatus(c)` を除外 |
| カスタムステータス | **親案件の** `customStatus` に対して既存 `matchCustomStatus(parent)` で判定（親経由の継承） |
| 担当者複数選択 | `selectedAssignees` が空なら全員。非空なら `c.assigneeId ?? 'unassigned'` が配列に含まれる子のみ |
| `hideUndated` | `resolveRange(c, 'child')` が null の子を除外 |

グループ化・並び順:

- キー: `c.assigneeId ?? 'unassigned'`。**ID 基準**でグループ化（名前は表示用）。表示名は子の `assignee`（未割当グループは `未割当`）。
- グループ順: 名前で `localeCompare(name, 'ja')` 昇順、**未割当グループは常に末尾**。
- グループ内: 開始日昇順（`start || '9999-12-31'` で比較）、同日なら課題キー順。`filter.childSort` はこのビューでは使わない。
- 子が 1 件も残らない担当者はグループ自体を出さない（課題ゼロ担当者の表示機能は**作らない**。質問票 Q4 で不採用）。

### 3.4 担当者の複数選択フィルタ UI

1 段目 filter-bar の単一選択 select の位置に、担当者別モード時のみ表示するドロップダウンを置く:

- トグルボタン（`.select-filter` 流用可）: ラベルは選択なし時 `👥 担当者: 全員`、選択あり時 `👥 担当者: N名`。
- クリックでパネル（`position:absolute` のポップオーバー）を開閉。パネル内容:
  - 「全解除」ボタン（`selectedAssignees = []` = 全員表示に戻す）
  - 担当者ごとの `<label><input type="checkbox">名前</label>` 一覧 + 最後に「未割当」
- **候補リスト** = `/api/project-users`（`ChildModal.init` が取得したものを共用するか、gantt 側でも fetch する。二重管理を避けるため `ChildModal` に getter を生やすより gantt 側で自前 fetch してよい — 1h キャッシュ付き API なので負荷は無視できる）と、`allData` の全子課題に実在する `{assigneeId, assignee}` の**和集合**（プロジェクトから外れたユーザーの課題を漏らさないため）。名前五十音順、未割当は末尾。
- チェック変更のたびに `selectedAssignees` を更新 → localStorage 保存 → `renderGantt()`。**パネルは閉じない**（連続チェックできるように）。
- パネルの DOM は `renderGantt()` が innerHTML を書き換える領域（`ganttHead` / `ganttRows`）の**外**（filter-bar 内）に置くこと。60 秒ポーリングの再描画で閉じない・チェック状態が飛ばないことが要件。パネル外クリックで閉じる（`document` の click リスナで判定）。
- 存在しなくなった ID が保存されていた場合はチェックなしとして無視する（エラーにしない。復元時に候補と突き合わせて除去まではしなくてよい）。

### 3.5 担当者別ビューの描画

`renderGantt()` の冒頭で分岐し、担当者別は `renderAssigneeGantt()`（新設）へ。共通部分（軸構築・ヘッダ・背景レイヤー・スクロール位置保持・空状態表示）は可能な限り関数を共用する。

- **軸**: `buildAxis(rows)` は `{range, children}` の配列を受ける想定なので、グループを `{ range: null, children: group.children }` に写像して渡せばそのまま使える（`take(range)` は null 安全）。
- **ヘッダ左ペイン**: `案件 / 課題` → 担当者別では `担当者 / 課題`、件数表示は `N名 / M課題`。
- **グループヘッダ行**:

```html
<div class="grow is-group">
  <div class="gcell-left" style="width:{LEFT_W}px">
    <button class="toggle-btn open" onclick="toggleGroup('a:12345')">▶</button>
    <span class="group-name">👤 山田太郎</span>
    <span class="count-badge">5</span>
    <span class="assignee-tag">計 40h/32h</span>   <!-- 予定h合計/実績h合計 -->
  </div>
  <div class="gtrack" style="width:{axis.width}px"></div>  <!-- バーなし -->
</div>
```

  - `.is-group` 用 CSS を追加: 背景 `var(--bg3)`、`font-weight:500` 程度で子行と区別。トラック側は空（バーを描かない）。
  - 開閉は `toggleGroup(key)` → `collapsedGroups` を反転 → `renderGantt()`。
- **子課題行**: 既存の `.grow.is-child` 行をベースに、課題キーの後ろに**親案件キー**を追加表示:

```html
<a href="{parent.url}" target="_blank" rel="noopener" class="issue-key parent-ref" title="{parent.title}">[{parent.id}]</a>
```

  - `.parent-ref` は `color: var(--text3); font-size: 10px;` 程度に落とす。`title` 属性で親タイトルがホバー表示できる。
  - バーは既存 `barCell(c, 'child')` をそのまま使用。ツールチップは既存 `showTip`（`findItem` が親を解決して「親案件」行を出す機能が既にある）をそのまま使用。
- **空状態**: 該当 0 件時は既存 `showState('🔍', ...)` を使い「該当する課題がありません」。
- `updateHideChipLabel` / `countUndated` はモード分岐し、担当者別では**子課題のみ**を数える。

### 3.6 案件別モードの回帰禁止

案件別モードの表示・挙動は一切変えないこと（`visibleRows` / 行 HTML / フィルタ挙動 / `bpm2-filter` の読み書き）。唯一の変更は次フェーズの「子課題件名クリックでモーダル」のみ。

## 4. フェーズ3: gantt.html へのモーダル組み込み

- `<head>` に `child-modal.css`、インライン `<script>` の前に `child-modal.js` を読み込む。
- 起動時に `ChildModal.init({ findChild, onDataChanged })` を呼ぶ:
  - `findChild: (id) => { const f = findItem(id); return f && f.kind === 'child' ? { child: f.item, parent: f.parent } : null; }`（`ChildModal` が期待する形に合わせる。フェーズ1で決めた interface に従うこと）
  - `onDataChanged: () => fetchData(true)`（バックエンドは変更 API 内で snapshot を同期更新済みのため、直後の再取得で反映される）
- **両モードの子課題行**で、件名 `<span class="issue-title">` をクリック可能にする: index.html の子課題タイトルと同じ見た目（`cursor:pointer` + 点線下線）で `onclick="openChildModal('{id}')"`。課題キーのリンク・バーのクリック（Backlog を開く）は**変更しない**。
- モーダルを開いたまま 60 秒ポーリングが走っても、モーダルは `ganttRows` の外（body 直下）にあるため再描画で消えないこと。編集中の入力値が失われないことを確認する。
- 担当者を変更して保存した場合、再取得後の担当者別ビューで課題が新しい担当者のグループへ移動することを確認する。

## 7. 動作確認手順

チェックリスト（改修計画書 6 章と同一。フェーズごとに該当項目を実施）:

4. 未割当グループが末尾に表示され、フィルタで「未割当」のみも選べる。
5. 健全性 / 状態 / hideDone / カスタムステータス / 日付なし / 粒度 が担当者別モードで指示書 3.3 の表のとおり効く。

7. ライト/ダーク両テーマで表示崩れがない（グループヘッダ・複数選択パネル・親キー表示含む）。
8. 60 秒ポーリング時に開閉状態・スクロール位置・ドロップダウン開状態とチェックが保持される。
9. 一覧の回帰: 子課題モーダル（保存・実績追加/削除・部分更新）と単独 worklog モーダルが改修前と同一に動く。コンソールエラーなし。

11. モーダルを開いたまま 60 秒ポーリングが走っても編集中の入力値が失われない。
