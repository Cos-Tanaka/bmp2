# 質問票：ガントチャート 案件別ビューを優先度・優先順位順に並べる

`docs/改修計画書_ガント案件別_優先度順表示.md` のドラフトに対する確認事項です。各項目に**推奨案**を記載しています。「推奨で可」の一言でも回答になります。
（優先度: ★★★ = 実装前に必須 / ★★ = 実装中に決めれば間に合う / ★ = 将来検討でも可）

## Q1. 「優先度」と「優先順位」のどちらを先に見るか ★★★

ご要望の「優先度『高』『中』『低』でかつ優先順位の数値が低い数値が上位」を、次のように解釈しています。

- **推奨: 優先度で大きく分け、同じ優先度の中で優先順位の小さい順**。優先順位が空欄の案件は、**同じ優先度の中で**優先順位ありの案件の後ろに並べる。
  - 例: 高(1) → 高(2) → … → 高(空欄) → 中(1) → 中(2) → … → 中(空欄) → 低 …
  - つまり「中・優先順位 1」は「高・優先順位空欄」より**下**になります。
- 代案: 優先順位を最優先にし、優先順位ありの案件を優先度に関係なく先頭に集める（中(1) が 高(空欄) より上）。

現状、優先順位が入っているのは 7 件ですべて「高」のため、今のデータではどちらでも同じ結果ですが、今後「中」に優先順位を付けた場合に差が出ます。→ 推奨案でよいですか？

→ 推奨案でOK

## Q2. Kintone番号の比較方法と、形式の違う番号・空欄の扱い ★★★

Kintone番号は文字列項目で、実データでは次の 3 種類があります（親案件 105 件中）。

| 形式 | 件数 | 例 |
|---|---|---|
| `s-` + 数字 | 100 件 | `s-1479`, `s-1515` |
| `s-` 以外 + 数字 | 1 件 | `help-15825`（V2A9-1527） |
| 空欄 | 4 件 | V2A9-2274 / 463 / 985 / 1101 |

- **推奨:**
  1. `s-` の番号は**数値部分で比較**（文字列のままだと `s-999` が `s-1000` より後ろになるため）。
  2. `help-` など `s-` 以外の形式は、`s-` の案件の**後ろ**に（その中では数値順）。
  3. 空欄はさらにその**後ろ**に、登録日の古い順。
- 代案 A: 接頭辞を無視して数値だけで比較（`help-15825` は数値が大きいため、結果的に末尾付近に来ます）。
- 代案 B: 空欄を先頭に置く（番号未採番＝新しい案件として目立たせる等の意図がある場合）。

→ 推奨案でよいですか？ また、`help-` 以外に今後使われうる接頭辞があれば教えてください。

→ 推奨案でOK

## Q3. 「Backlogの登録日が若い順」の位置付け ★★★

「優先順位が空欄は、Kintone番号の若い順、Backlogの登録日が若い順」を次のように解釈しています。

- **推奨: Kintone番号で比較し、同じ番号（重複）や番号が空欄のときに登録日の古い順で並べる**（登録日は第 2 キー）。
  - 実データでも同じ Kintone番号を持つ案件があります（例: `s-1479` が V2A9-2417 と V2A9-1588 の 2 件）。
- 代案: 登録日を Kintone番号より先に見る（その場合 Kintone番号はほぼ効かなくなります）。

また「若い順」は**古い順（日付の小さい順）**の意味でよいですか？

→ 推奨案でOK

## Q4. 優先順位が同じ値・飛び番のとき ★★

- 同じ優先度・同じ優先順位の案件が複数ある場合、**推奨: Kintone番号 → 登録日の順**（空欄時と同じ規則）で並べます。
- 現状、V2A9-2467 の優先順位が **30**（他は 1〜6）です。そのまま「6 の次」に並びますが、意図した値かご確認ください（入力誤りであれば Backlog 側で修正いただく想定です）。

→ 推奨案でOK

## Q5. 一覧画面（index.html）にも同じ並び順を適用するか ★★★

ご要望は「ガントチャートの案件別ビュー」のみでした。

- **推奨: 今回はガント案件別ビューのみ**。並び替えはガント画面内で行い、一覧画面の順序は現行のまま（バックエンドは項目を追加するだけ）。
- 代案: 一覧画面も同じ順にする（その場合はバックエンド側で並べて返すのが簡単で、全画面で順序が揃います）。

→ 推奨案でOK

## Q6. 担当者別ビューの案件順 ★★

担当者別ビュー（担当者 → 案件 → 子課題）では、現在、担当者ごとの案件を「その担当者の子課題の最も早い開始日」順に並べています（空き時間を見やすくするため）。

- **推奨: 担当者別ビューは現行のまま**（今回の対象外）。
- 代案: 担当者別ビュー内の案件順も優先度・優先順位順にする。

→ 推奨案でOK

## Q7. 左ペインに優先度・優先順位を表示するか ★★

並び順の根拠が画面から分からないと、「なぜこの案件が上なのか」が判別しづらくなります。

- **推奨: 親案件行の健全性アイコンの右に小さなバッジを表示**（例: 優先度「高」は赤系の `高`、優先順位があれば `高1` のように番号を併記。「中」「低」は控えめな色、またはバッジ非表示）。件名の幅は 1〜2 文字分減ります。
- 代案 A: 表示しない（ツールチップにのみ出す）。
- 代案 B: 優先度・優先順位・Kintone番号をすべて表示。

→ 推奨案でOK
