# 改修計画書：ガントチャート 左ペイン（案件 / 課題）幅の拡張

- 作成日: 2026-08-25
- 対象: `frontend/html/gantt.html`（フロントエンドのみ。バックエンド・API 変更なし）
- ステータス: **確定版**（2026-08-25 `docs/質問票_ガント左ペイン幅拡張.md` の回答を反映。Q1〜Q10 すべて推奨案を採用）
- 位置づけ: ガント画面の**改修要望 1**。要望 2（担当者行の集約帯）・要望 3（担当者→親案件→子課題の 3 階層）は `docs/改修計画書_ガント担当者別ビュー改善.md` を参照

## 1. 背景・目的

| 要望 | 目的 |
|---|---|
| ガントチャートの「案件 / 課題」列（左ペイン）の幅を広げ、子課題の件名が読めるようにする | 現状は件名が数文字で「…」に切れ、どの課題のバーか判別できない |
| スケジュール（時間軸）側は全体的に幅を狭めてよい | 横スクロール対応済みのため、1 画面に収まる期間が多少減っても運用上の支障がない |

## 2. 現状分析：なぜ件名が読めないのか

左ペインは `LEFT_W = 340px` の固定値です（[gantt.html:379](frontend/html/gantt.html:379)）。この 340px を、トグル・健全性アイコン・課題キー・件数バッジ・担当者名などが先に消費し、**件名は「残り」しか使えません**。

行種別ごとの内訳（概算。課題キーは `ASPIT-1234` 相当の 10 文字、mono 11px ≒ 6.6px/文字で試算）:

| 行種別 | 固定要素の合計（概算） | 件名に残る幅 | 表示できる全角文字数 |
|---|---|---|---|
| 親案件行（案件別） | 余白18 + トグル16 + 健全性13 + キー66 + 件数バッジ26 + 担当者72 + gap30 ≒ 241px | **約 99px** | 13px 文字で **約 7 文字** |
| 子課題行（案件別） | インデント26 + スペーサ16 + キー66 + 担当者72 + 余白10 + gap18 ≒ 208px | **約 132px** | 12px 文字で **約 11 文字** |
| 子課題行（担当者別） | インデント26 + スペーサ16 + キー66 + 親案件キー62 + 余白10 + gap18 ≒ 198px | **約 142px** | 12px 文字で **約 11 文字** |

※ `日付未設定` バッジが出る行では、さらに約 66px（バッジ＋gap）が件名から引かれます。

補足（レイアウト上の性質）:

- `.issue-title` は flex 子で `overflow:hidden; text-overflow:ellipsis`、`.assignee-tag` は `margin-left:auto` です。したがって**左ペインを広げた分は、まず件名が自然な幅まで伸びるのに使われ**、件名が収まりきったあとの余りが担当者タグ手前の余白になります（＝幅拡張はそのまま件名の可読性向上に効く）。
- 一方で `LEFT_W` は JS 定数として 12 箇所のインライン `style="width:…"` に埋め込まれ、さらに CSS 側にも年月ラベルの貼り付き位置として `347px`（= 340 + 余白 7）がハードコードされています（[gantt.html:148](frontend/html/gantt.html:148)）。**幅を変えるにはこの二重管理を解消する必要があります**（3.1）。

## 3. 改修方針

### 3.0 方式の比較

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（推奨）** | 既定幅を拡大したうえで、**ヘッダーの境界をドラッグして幅を変えられる**ようにし、`localStorage` に保存 | 案件名の長さ・画面サイズ・利用者の好みに一発で合う。以後この種の要望が再発しない | 実装が A/B/C 中で最大（それでも半日規模） |
| B | `LEFT_W` を固定値で拡大するだけ（例: 340 → 520） | 最小コスト | 「もう少し広く／狭く」の再調整のたびに改修が必要。ノート PC など狭い画面では広すぎる |
| C | 幅プリセットのチップ（`狭い 340` / `標準 480` / `広い 620`）を追加 | ドラッグ実装が不要で切替は可能 | 粒度が粗い。フィルタバーのチップがさらに増える |

→ **A 案で確定**（Q1。既定幅の拡大 ＋ ドラッグリサイズ ＋ 永続化）。B は A の実装の一部であり、既定幅は 3.2 のとおり 520px とする。

### 3.1 幅の可変化（実装の土台。A/B/C どの案でも必要）

- JS 定数 `LEFT_W` を**可変の状態値 `leftW`** に変更し、値は `.gantt-canvas` に **CSS 変数 `--left-w`** として設定する。
- 各行の `style="width:${LEFT_W}px"` は削除し、`.gcell-left { width: var(--left-w) }` に一本化する（インライン 12 箇所を CSS 1 行へ）。
- 年月ラベルの `left: 347px` は `left: calc(var(--left-w) + 7px)` に置き換え、ハードコードを排除する。
- ヘッダー／行コンテナの全体幅は `calc(var(--left-w) + ${axis.width}px)` とする。
- 効果として、**幅の変更は CSS 変数の更新だけで反映され、行の再描画（`renderGantt`）は不要**になる。ドラッグ中も 60fps で追従し、展開状態・スクロール位置も保持される。
- `scrollToToday()`（[gantt.html:1016](frontend/html/gantt.html:1016)）は `leftW` を参照する形に直す。

### 3.2 既定幅と可変範囲（Q2 で確定）

| 項目 | 値 | 根拠 |
|---|---|---|
| 既定幅 | **520px**（現行 +180px） | 子課題の件名に約 310px＝全角 **約 26 文字**、親案件で約 21 文字を確保できる |
| 最小 | 260px | 課題キー＋数文字は残る下限 |
| 最大 | 800px | 時間軸が実用的な幅を保てる上限 |
| リセット | 境界をダブルクリックで既定幅へ | 誤って極端な幅にしたときの復帰手段 |
| 永続化 | `localStorage: bpm2-gantt-leftw` | 既存の `bpm2-gantt-scale` などと同じ方式（`bpm2-filter` には入れない＝index.html と共有する filter オブジェクトを汚さない） |
| 適用範囲 | 案件別・担当者別で**共通の 1 値** | Q7。モード別保存はしない（設定をシンプルに保つ） |

### 3.3 時間軸（列幅）の縮小（Q3 で確定）

要望どおり時間軸側は狭め、左ペイン拡張ぶんを吸収します。`SCALES`（[gantt.html:380](frontend/html/gantt.html:380)）の `colW` を変更:

| 粒度 | 現行 | 変更後 | ラベル成立性（mono 10px） |
|---|---|---|---|
| 日 | 32px | **28px** | `25` ＋曜日 `月` ＝ 約 25px。収まる |
| 週 | 52px | **44px** | `8/25` ＝ 約 26px。収まる |
| 月 | 64px | **56px** | `8月` ＝ 約 18px。収まる |

1920px 幅の画面で「1 画面に見える期間」は次のとおりで、**左ペインを 180px 広げても現行とほぼ同等**を維持できます:

| 粒度 | 現行（左340 / 軸1580） | 変更後（左520 / 軸1400） |
|---|---|---|
| 日 | 約 49 日 | 約 50 日 |
| 週 | 約 30 週 | 約 31 週 |
| 月 | 約 24 ヶ月 | 約 25 ヶ月 |

### 3.4 左ペイン内の情報配置の見直し（Q5・Q6 で確定）

幅拡張に伴い、件名以外の要素も現実的な表示に整える（いずれも小さな CSS 変更）:

- `.assignee-tag` の `max-width: 72px` → **110px**（Q6。日本語氏名がフルネームで読める幅）。件名を優先するため `flex: none` は維持し、はみ出しは従来どおり省略＋ツールチップ。
- 子課題行のインデント `padding-left: 26px` は維持（階層の見た目を変えない）。
- 担当者別ビューの子課題行に出している親案件キー `[ASPIT-1234]` は**現状維持＝キーのみ**（Q5。親案件名は従来どおりツールチップで確認する。広がった幅は子課題の件名に優先して使う）。

### 3.5 件名が幅を超える場合の扱い（Q4 で確定）

**現行どおり 1 行＋末尾 `…` 省略＋`title` 属性のツールチップ**とする（行高 30/34px を変えないため、1 画面の表示件数が減らない）。2 行折り返し案は不採用（行高が変わると背景グリッド・バー位置の縦計算に影響するため）。

### 3.6 狭い画面での安全弁（Q8 で確定）

`leftW` は保存値をそのまま使うが、描画時に `Math.min(leftW, window.innerWidth - 320)` でクランプし、**時間軸が 320px 未満にならない**ようにする（保存値そのものは書き換えない＝広い画面に戻れば元の幅で表示）。

## 5. 影響範囲・リスク

- **バックエンド・API 変更なし**。リリースは `docker compose restart frontend` のみ（bind mount 済み）。
- **index.html への影響なし**。共有する `bpm2-filter` は触らず、新しい localStorage キーを 1 つ増やすだけ。
- **sticky の破綻に注意**: 左ペインは `position: sticky; left: 0`、年月ラベルは `left: calc(var(--left-w) + 7px)` で貼り付く。CSS 変数化のあと、**横スクロール時に年月ラベルが左ペインに隠れない／離れない**ことの確認が必須（既存コメントのとおり `.gt-group` に `overflow:hidden` を付けると sticky が効かなくなる点も維持）。
- **背景レイヤーとの整合**: グリッド・週末・今日線は `.gantt-bg { left: LEFT_W }` の 1 枚もの。ここも変数化するため、ドラッグ中にバーと背景がズレないことを確認する。
- **列幅縮小によるラベル潰れ**: 日粒度の「日＋曜日」が最も窮屈。実データで 1 桁日／2 桁日の両方を確認する。
- **バー最小幅**: `barCell` は幅を `Math.max(…, 6)` でクランプ済みのため、列幅縮小で 1 日バーが消えることはない（日粒度 28px、月粒度でも 1 日 ≒ 1.9px → 6px にクランプ）。
- **ドラッグ操作の取りこぼし**: ドラッグ中に `pointercapture` を使い、行の `onclick`（モーダル起動）が誤発火しないようにする。

## 6. テスト計画（手動）

1. 既定表示: 案件別・担当者別の両モードで、子課題の件名が従来より明確に長く表示されること。
2. ドラッグ: 境界をつまんで左右に動かすと、左ペイン・時間軸・背景グリッド・今日線・バーがすべて同時に追従すること。最小／最大でクランプされること。
3. ダブルクリックで既定幅へ戻ること。
4. リロード後・別ページ往復後に幅が保持されること。60 秒ポーリングの再描画でも幅が保持されること。
5. 横スクロール時、年月ラベルが左ペイン右端に貼り付いたまま読めること（幅変更後も）。
6. 粒度 日／週／月それぞれで、ヘッダーのラベルが省略・重なりなく読めること。「📍 今日へ」が中央にスクロールすること。
7. 子課題の件名クリックで詳細モーダルが開くこと（ドラッグ後も誤作動しないこと）。
8. ライト／ダークテーマ両方。
9. 1366px 幅のノート PC 相当で、時間軸が実用幅を保つこと（3.6 のクランプ）。
10. index.html のフィルタ・`childSort` がガント往復で変化しないこと（回帰）。
