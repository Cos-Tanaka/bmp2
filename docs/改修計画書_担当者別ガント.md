# 改修計画書：ガントチャート 担当者別ビュー

- 作成日: 2026-07-31
- 対象: `frontend/html/gantt.html`・`frontend/html/index.html`（フロントエンドのみ。バックエンド変更なし）
- ステータス: **確定版**（2026-07-31 質問票の回答を反映。全項目で推奨案を採用、Q4 の「課題ゼロ担当者の表示」は不採用、追加要望として「ガントから子課題詳細モーダルを開く」を 3.6 節としてスコープに追加）

## 1. 背景・目的

| 要望 | 目的 |
|---|---|
| ガントチャートを担当者でグルーピングし、担当者のスケジュールを見えるようにする | 担当者にタスクが割り当たっているかを確認したい／担当者の空きを減らしたい |
| 担当者別ビューでは親課題を表示せず、子課題のみ表示する | 実作業の単位（子課題）でスケジュールを見たい |
| 担当者フィルタを複数選択できるようにする | チームリーダーが自チームメンバーだけを確認したい。メンバー構成は適時変わる |

## 2. 改修方針

**既存の `gantt.html` に「表示モード切替（案件別 / 担当者別）」を追加する**（新ページは作らない）。

理由:
- 時間軸モデル（`buildAxis` / `xOf` / `dayW`）、バー描画（`barCell`）、健全性判定（`childHealth`）、ツールチップ、粒度切替、今日線、テーマなど、ガント描画資産の大半をそのまま共用できる。
- ページを分けると上記の重複コピーが生じ、以後の修正が二重になる（本プロジェクトはビルドなしの素の HTML のため、共通化手段がページ内共有しかない）。
- ユーザー動線も「同じ画面でモードを切り替える」方が自然。

バックエンドは改修不要:
- `/api/issues` の子課題には `assignee`（名前）と `assigneeId`（Backlog ユーザー ID、未割当は `null`）が既に含まれる（`format_issue`）。
- 担当者一覧は `/api/project-users`（`[{id, name}]`、1h キャッシュ）が既存。プロジェクト参加者のうち「課題を1件も持たない人」もここから取得でき、「空き（タスクゼロ）の人」の検出に使える。

## 3. 機能仕様

### 3.1 表示モード切替

- 粒度チップの並びに「表示」モードチップを追加: `📋 案件別`（現行表示）/ `👤 担当者別`。
- 選択状態は localStorage 新キー `bpm2-gantt-mode` に保存（`bpm2-filter` には入れない。index.html と共有する filter オブジェクトを汚さないため）。
- 案件別モードは現行動作を一切変えない（回帰ゼロを目標）。

### 3.2 担当者別ビューの行構成

```
👤 山田太郎 (5件)  計 40h/32h          ← グループヘッダ行（開閉トグル付き、sticky 左ペイン）
    PROJ-123 子課題タイトル   [親: PROJ-100]   ▬▬▬▬▬
    PROJ-124 子課題タイトル   [親: PROJ-101]     ▬▬▬▬
👤 鈴木花子 (3件) ...
👤 未割当 (12件) ...                    ← 末尾に固定
```

- **データ構築**: `allData` の全親の `children` をフラット化し、`assigneeId`（`null` = 未割当）でグループ化。親課題の行は出さない。
- **グループヘッダ行**: 担当者名・表示中の課題件数・（案として）予定/実績工数合計。クリックで開閉。開閉状態は既存 `expanded` Set を流用（キーは `assignee:<id>` 形式で親案件 ID と衝突しないようにする）。
- **子課題行**: 既存の `is-child` 行スタイル・`barCell(c, 'child')`・ツールチップを流用。左ペインに**親案件のキー**を補足表示する（同名の子課題（例: 「詳細設計」）がどの案件のものか判別できないため）。ツールチップには既に親案件行がある。
- **バーの色・塗り・予定線**: 既存の `childHealth` / 進捗率 / `planProgressOf` をそのまま使用。
- **並び順**: グループは担当者名の五十音順（`localeCompare('ja')`）、未割当グループは末尾。グループ内の子課題は開始日昇順（空きの視認を優先。`childSort` 設定はこのビューでは使わない）。

### 3.3 担当者の複数選択フィルタ

- **UI**: 担当者別モード時、既存の単一選択 `<select>`（`assigneeFilter`）を隠し、代わりに**チェックボックス式ドロップダウン**を表示する。
  - ボタンに現在の選択を要約表示（例: `👥 担当者: 3名` / 全員時は `👥 担当者: 全員`）。
  - パネル内: 全員選択/解除、担当者ごとのチェックボックス、未割当。
  - 候補は `/api/project-users` と表示データ中の担当者の和集合（退場済みユーザーが持つ課題も漏らさない）。
- **マッチング基準**: `assigneeId`（数値）で行う。名前は同姓同名で衝突しうるため（CLAUDE.md 記載のとおり backend が ID を返すのはこのため）。未割当は `null` を専用値として扱う。
- **永続化**: localStorage 新キー `bpm2-gantt-assignees`（ID 配列、空配列 = 全員）。ブラウザごとに保存されるため、チームリーダーは一度選べば次回以降も自チームだけが表示され、メンバー変更もチェックの付け外しだけで済む（＝「適時変更する」要件への回答。サーバ側にチーム定義は持たない）。
- **既存単一フィルタとの関係**: `bpm2-filter.assignee`（index.html と共有）には**書き込まない**。案件別モードと index.html の動作は現状維持。

### 3.4 既存フィルタの適用（担当者別モード時）

| フィルタ | 案件別（現行） | 担当者別での扱い |
|---|---|---|
| 健全性 | 親の `health` | 子課題の `childHealth(c)` で判定 |
| 状態 (対応中/完了) | `isParentDone` | 子課題自身の `isDoneStatus(c)` で判定 |
| ✅ 処理済み・完了を隠す | 親を隠す＋展開子を除外 | `isDoneStatus(c)` の子課題を除外（既定挙動そのまま） |
| ステータス（カスタム） | 親の `customStatus` | **親経由で継承**（子課題にこのフィールドは無いため、親案件のステータスが条件に合う子課題のみ表示） |
| 日付なしを隠す | 行の期間解決可否 | 子課題の `resolveRange(c,'child')` 可否（既定 ON のまま） |
| 粒度 / 今日へ / 全て開く・閉じる | — | そのまま動作（開閉対象がグループになる） |

### 3.5 「空き」の見え方（質問票 Q1・Q4・Q7 で確定）

担当者ごとの行が縦に並び、グループ内は開始日昇順のため、**バーが無い期間＝空き**として目視できる。
- 課題ゼロの担当者を「0件」ヘッダとして出す機能は**不採用**（Q4: プロジェクトに関係しないユーザーも多数登録されておりノイズになるため）。
- 多重アサイン警告・稼働率計算・空き期間ハイライトは**見送り**（Q7）。1課題1行の縦積み（Q1: A 案）とする。

### 3.6 子課題の詳細モーダル（追加要望）

ガントチャートの**案件別・担当者別どちらのモードでも**、子課題の件名クリックで一覧画面と同じ詳細モーダルを開き、**担当者・実績（作業時間）・進捗・日付・チェック状態を登録できる**ようにする。

- **実現方式**: index.html にあるモーダル一式を共有ファイルへ抽出し、両ページから読み込む（ビルド不要の `<script src>` / `<link>` 参照。bind mount のため反映は restart のみ）。
  - `frontend/html/child-modal.js` — `openChildModal` / `closeChildModal` / `saveChildEdits` / worklog パネル（`'dw'` プレフィックス系: `mountWorklogPanel`・`loadWorklogHistory`・`addWorklog`・`deleteWorklog`）/ `refreshChildModalHours` / `/api/field-options`・`/api/project-users` の取得。モーダルの HTML は JS から注入し、各ページの `<body>` に個別に書かない。
  - `frontend/html/child-modal.css` — モーダル関連スタイル（`.modal-overlay` ほか）。CSS 変数（`--bg2` 等）は両ページで同名のため、そのまま両テーマで動く。
  - index.html は抽出したファイルを参照する形にリファクタする（**挙動は不変**。テーブル側の `'w'` プレフィックスの単独 worklog モーダルは index.html 固有のため移動しない）。
- **ガント側の組み込み**:
  - 子課題行の**件名クリック**でモーダルを開く（一覧と同じ点線下線スタイルで押せることを示す）。課題キーのリンクとバークリックは現行どおり Backlog を開く（変更なし）。
  - 保存・実績追加/削除の成功後は `fetchData(true)` でガントを再描画する（バックエンドは変更系 API 内で `refresh_snapshot()` を同期実行済みのため、直後の再取得に反映される）。開いているモーダルは一覧と同様、閉じずに数値スパンのみ更新（`refreshChildModalHours`）。
  - `/api/field-options`・`/api/project-users` の取得を gantt.html の起動時にも行う（project-users は 3.3 の複数選択フィルタの候補としても共用）。
- これによりガントは「閲覧専用」ではなくなる（バーのドラッグ編集は引き続きスコープ外）。実装完了時に CLAUDE.md の該当記述を更新する。

## 5. 影響範囲・リスク

- **index.html への影響なし**: 共有している `bpm2-filter` の構造は変えない。新規 localStorage キーのみ追加。
- **バックエンド・API 変更なし**: リリースは `docker compose restart frontend` のみ（bind mount 済み）。
- **60 秒ポーリング再描画**: 既存同様、開閉状態（`expanded`）とスクロール位置を保持する。複数選択フィルタのドロップダウンを開いている最中の再描画でパネルが閉じないよう、パネル部分は `renderGantt` の外に置く。
- **行数**: 全子課題フラット表示は最大でも「全て開く」時の現行行数と同等（live データで数百行）。現行実装が innerHTML 一括生成で問題なく動作している範囲。
- **同姓同名**: ID 基準のため誤マージしない。逆に、Backlog 上の別 ID・同名ユーザーは別グループとして並ぶ（正しい挙動として扱う）。
- **退場済みユーザー**: `/api/project-users` に居ないが課題に残っている担当者は、表示データ側から候補に補完するため漏れない。
- **モーダル抽出のリファクタ**: index.html の稼働中コード（約 400 行）を移動するため、一覧側の回帰リスクが最も高い箇所。「挙動不変の抽出」に徹し（ロジック変更を混ぜない）、テスト計画 9〜11 で一覧・ガント両方のモーダル動作を確認する。`'w'` プレフィックスの単独 worklog モーダルは移動しないため影響しない。

## 6. テスト計画（手動）

1. モード切替の往復で表示・スクロール・開閉が破綻しないこと。案件別モードが改修前と同一であること。
2. 担当者別: 親課題行が出ないこと。全子課題が担当者ごとに漏れなく重複なく現れること（件数照合）。
3. 複数選択: 2〜3 名選択 → 対象者のみ表示。全解除 → 全員表示。リロード・翌日アクセスで選択が保持されること。
4. 未割当グループの表示と、未割当のみ選択のフィルタ。
5. 既存フィルタ（健全性 / 状態 / hideDone / カスタムステータス / 日付なし / 粒度）が担当者別モードで 3.4 のとおり効くこと。
6. index.html との localStorage 往復（ガント→一覧→ガント）で一覧側のフィルタ・childSort が変化しないこと。
7. ライト/ダークテーマ両方での表示確認。
8. 60 秒ポーリング時に開閉・スクロール・ドロップダウン開状態が保持されること。
9. **一覧画面の回帰**: モーダル抽出後、index.html の子課題モーダル（担当者・進捗・日付・チェック状態の保存、実績の追加・削除、`refreshChildModalHours` による部分更新）が改修前と同一に動くこと。単独 worklog モーダル（実績セルクリック）も同様。
10. **ガントのモーダル（両モード）**: 件名クリックで開き、担当者と実績を登録 → 保存後にバー・グループ（担当者変更時は所属グループ）へ反映されること。課題キー・バーのクリックは従来どおり Backlog が開くこと。
11. モーダルを開いたまま 60 秒ポーリングが走っても、編集中の入力値が失われないこと。
