# 質問票：ガントチャート 左ペイン（案件 / 課題）幅の拡張

`docs/改修計画書_ガント左ペイン幅拡張.md` のドラフトに対する確認事項です。各項目に**推奨案**を記載しています。「推奨で可」の一言でも回答になります。
（優先度: ★★★ = 実装前に必須 / ★★ = 実装中に決めれば間に合う / ★ = 将来検討でも可）

## Q1. 幅の決め方 ★★★

- **A 案（推奨）: 既定幅を広げたうえで、境界をドラッグして自由に変えられるようにする**（幅はブラウザに保存。ダブルクリックで既定へリセット）
  → 案件名の長さや画面サイズが人によって違っても、各自で合わせられる。以後「もう少し広く／狭く」の改修が発生しない。
- B 案: 固定値で広げるだけ（例 340 → 520px）。最小コスト。ただし再調整のたびに改修が必要。
- C 案: 幅プリセットのチップ（`狭い` / `標準` / `広い`）を追加。

→ A 案でよいですか？

→ A案で良い

## Q2. 既定幅の値 ★★★

推奨は **520px**（現行 340px から +180px）です。このとき件名に使える幅は概算で:

| 行種別          | 現行         | 520px 時        |
| ------------ | ---------- | -------------- |
| 親案件（13px 文字） | 全角 約 7 文字  | 全角 **約 21 文字** |
| 子課題（12px 文字） | 全角 約 11 文字 | 全角 **約 26 文字** |

- 確認 1: 520px（子課題で全角 26 文字程度）で足りますか？ 実際の子課題名で「これが読めれば十分」という代表例をいくつか挙げていただけると、既定値を実データに合わせて決められます。
- 確認 2: 主に使っている画面の横幅はどれくらいですか？（例: 1920px のデスクトップ / 1366〜1600px のノート PC）。狭い画面が主なら既定値を 440〜480px に下げます。

→ OK

## Q3. 時間軸（列幅）を狭めることの確認 ★★★

「スケジュール側は狭めてよい」とのご要望を受け、列幅を **日 32→28px / 週 52→44px / 月 64→56px** に縮める想定です。
これにより 1920px 画面で 1 画面に見える期間は、左ペインを 180px 広げても現行とほぼ同じ（週粒度で約 30 週 → 約 31 週）に保てます。

- 確認: この縮小幅で問題ないですか？（もっと詰めてもよい／逆に列幅は変えずに全体を横スクロールで見る、というご意向があればお知らせください）

→ OK

## Q4. 件名が幅を超えた場合の表示 ★★

- **推奨: 現行どおり 1 行で末尾を「…」省略**（マウスオーバーで全文をツールチップ表示）。行高が変わらないので、1 画面に表示できる課題数が減りません。
- 代案: **2 行折り返し**で全文を表示（行高が 30px → 46px 程度に増え、表示件数は約 2/3 に減少。バー位置の縦計算にも影響）。

→ 推奨（1 行＋省略）でよいですか？

→ 推奨案でOK

## Q5. 担当者別ビューで親案件名まで出すか ★★

前回の改修（担当者別ビュー）では、左ペイン幅 340px の制約から**親案件はキーのみ**（例 `[ASPIT-1234]`）の併記としました。今回の幅拡張で、親案件の**名称**も出す余地が生まれます。

- **推奨: キーのみのまま**（幅は子課題の件名に優先して使う。親案件名は従来どおりツールチップで確認）
- 代案: 件名の後ろに `— 親案件名` を薄字で併記（件名が長い行では親案件名から先に省略）

→ 推奨案でOK

## Q6. 担当者名の表示幅 ★★

現在、左ペイン右端の担当者名は **72px で打ち切り**（フルネームだと途中で「…」になります）。

- **推奨: 110px まで拡大**（日本語のフルネームがほぼ読める幅）
- 代案: 担当者名は表示しない（件名にさらに 110px 回す。担当者別ビューではグループ見出しに担当者が出るため冗長ではあります）

→ 推奨案でOK

## Q7. 案件別ビューと担当者別ビューで幅を分けるか ★

- **推奨: 両モード共通の 1 つの幅**（設定がシンプル）
- 代案: モードごとに別々の幅を保存（担当者別は親案件キーぶん多く消費するため、モードごとに最適化できる）

→ 推奨案でOK

## Q8. 狭い画面での挙動 ★★

ノート PC やタブレットで左ペインが画面を占有しすぎないよう、**時間軸が 320px を下回らない範囲に自動でクランプ**する想定です（保存した幅そのものは変えず、広い画面に戻れば元の幅で表示）。

- 確認: この挙動で問題ないですか？ また、タブレット等の小画面でガントを使う場面はありますか？（無ければクランプの閾値は簡易でかまいません）

→ OK

## Q9. 一覧画面（index.html）の列幅 ★

今回はガント画面のみが対象で、一覧画面のテーブル列幅は変更しない想定です。

- 確認: 一覧画面側でも件名が読みづらい等の不満はありますか？（あれば別件として対応します）

→ 今回はガント画面のみでOK

## Q10. スコープ外の確認 ★

以下は今回含めない想定です。問題ないですか？

- 左ペインの表示項目のカスタマイズ（健全性アイコン・件数バッジ・担当者の表示 ON/OFF）
- バーのドラッグによる日付変更（編集は従来どおり詳細モーダル経由）
- バックエンド・API の変更（不要）

→ OK
