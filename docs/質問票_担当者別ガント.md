# 質問票：ガントチャート 担当者別ビュー

改修計画書のドラフトに対する確認事項です。各項目に**推奨案**を記載しています。「推奨で可」の一言でも回答になります。
（優先度: ★★★ = 実装前に必須 / ★★ = 実装中に決めれば間に合う / ★ = 将来検討でも可）

## Q1. 担当者ごとの表示形式 ★★★

担当者のスケジュール表示には 2 案あります。

- **A 案（推奨）: グループヘッダ + 課題 1 件 1 行の縦積み**
  各課題の期間・進捗・健全性が明確。行数は増えるが、既存の行描画をそのまま使える。
- **B 案: 担当者 1 人 = 1 行に全バーを横並び（リソースビュー）**
  空き期間が一目で分かる反面、期間が重なる課題は段組みが必要で表示が複雑化。進捗率表示等が犠牲になる。実装規模も大。

→ A 案でよいですか？（「空きを減らす」目的の強さ次第では B 案や、A 案＋将来 B 案追加も検討します）

→ A 案でよい。並び順を開始日の昇順で並べると、空きも見やすい。

## Q2. 「チーム」の扱い ★★★

「チームリーダーは自チームだけ見たい」「メンバーは適時変更する」について:

- **推奨: ブラウザ保存のみ**。各自のブラウザにチェックした担当者が保存され、次回以降も維持。メンバー変更はチェックの付け外し。サーバ側にチーム定義は持たない。
- 確認: リーダーが複数端末を使う、他人の PC でも同じチーム設定を使いたい、「〇〇チーム」として名前を付けて保存・共有したい、といった要望はありますか？ ある場合はチームプリセット機能（サーバ保存 or 名前付きローカル保存）を別途設計します。

→ ブラウザ保存のみ。

## Q3. 未割当課題の表示 ★★★

「タスクが割り当たっているか確認したい」という目的から、**未割当の子課題は重要な情報**と考えます。

- **推奨: 「未割当」グループを末尾に常設**し、フィルタでも「未割当」を選択肢として選べるようにする。
- 確認: 未割当グループは既定で表示（推奨）/ 既定で非表示、どちらにしますか？件数が多い場合（現状の live データでは未割当が相当数ある想定）、既定で閉じた状態にする案もあります。

→ 「未割当」グループを末尾に常設

## Q4. 課題ゼロの担当者の表示 ★★

プロジェクト参加者のうち、表示期間に課題が 1 件も無い人は行が消えます。「空きを減らす」目的なら**タスクゼロの人こそ見たい**可能性があります。

- **推奨: 「課題なしの担当者も表示」トグルを追加**（既定 OFF）。ON にすると `/api/project-users` の全員が 0 件ヘッダとして並ぶ。
- 確認: このトグルは必要ですか？また、プロジェクト参加者にはレビューアや管理者など「タスクを持たない前提の人」が含まれますか？（多数含まれるなら 0 件表示はノイズになるため既定 OFF が妥当）

→ 今回は不要、このプロジェクトに関係無い人も登録されているため、タスクが０のメンバーも多数存在し、ノイズでしかない。

## Q5. 完了済み子課題の既定表示 ★★

現行の「✅ 処理済み・完了を隠す」チップは担当者別モードでもそのまま使えます。

- 確認: 担当者別モードでは**既定で ON**（完了を隠して現在〜将来の負荷だけ見せる）にしますか？それとも現行どおりユーザーの前回設定に従いますか？（推奨: 現行どおり設定共有。一覧と挙動が揃う）

→ 推奨でよい。

## Q6. 子課題行に出す親案件情報 ★★

親課題の行は出さないため、子課題がどの案件のものか分からなくなります。

- **推奨: 左ペインの子課題行に親案件キー（例: `PROJ-100`）を小さく併記**＋ツールチップに親案件名（既存機能）。
- 確認: 親案件の**タイトル**まで行内に出す必要はありますか？（左ペイン幅 340px の制約上、キーのみを推奨。必要なら左ペイン幅の拡張も検討）

→ 推奨を採用

## Q7. 空き・過負荷の強調表示 ★

今回は「担当者ごとに課題を縦に並べ、バーの無い期間＝空きを目視できる」ところまでをスコープとし、以下は見送る想定です。

- 同一担当者で期間が重複する課題（多重アサイン）の警告表示
- 予定工数と期間からの稼働率計算・ヒートマップ
- 空き期間そのもののハイライト

→ 見送りでよいですか？将来要望として温度感があれば教えてください（Q1 で B 案を選ぶ場合は一部が自然に実現します）。

→ 見送りでよい。

## Q8. カスタムステータスフィルタの継承 ★★

「概算見積〜本番リリース」のステータスは**親案件のフィールド**で、子課題は持っていません。担当者別モードでは「親案件のステータスが条件に合う子課題だけを表示」という継承方式を予定しています。

- 確認: この解釈で問題ないですか？（例: 「開発中」を選ぶと、開発中の案件に属する子課題のみが各担当者の行に残る）

→ はい。

## Q9. 並び順 ★

- グループ（担当者）: 名前の五十音順、未割当は末尾 — でよいですか？（代案: 課題件数の多い順）
- グループ内の課題: 開始日の昇順 — でよいですか？（一覧の `childSort` 設定はこのビューでは適用しない想定）

→ よい。

## Q10. スコープ外の確認 ★

以下は今回含めない想定です。問題ないですか？

- ガント上でのドラッグによる日付・担当者の変更（閲覧専用を維持。編集は一覧画面の子課題モーダル）
- 一覧画面（index.html）側への担当者複数選択の展開（要望があれば別件として対応可能）
- バックエンド・API の変更（不要と確認済み）

→ よい。

→ ガントチャート（案件別／担当者別のどちらも）で、子課題の件名をクリックで、詳細モーダルを開くことは出来るか？これで担当者も実績も登録出来るようにしたい。

### 【回答】可能です。スコープに追加しました（計画書 3.6 節）

- 一覧画面の子課題モーダル（担当者・進捗・開始/期限日・チェック状態の編集＋実績の追加/削除）を共有ファイル `child-modal.js` / `child-modal.css` へ抽出し、一覧・ガントの両ページから読み込みます。ビルド工程のないプロジェクトのため、コピーではなくファイル共有で二重管理を避けます。
- ガントでは両モードとも**子課題の件名クリック**でモーダルが開きます（一覧と同じ点線下線の見た目）。課題キーのリンクとバーのクリックは従来どおり Backlog を開きます。
- モーダルが使う API（`/api/field-options`・`/api/project-users`・課題 PATCH・実績 API）はすべて既存で、バックエンド変更は不要です。保存後はガントを再取得してバーに即反映します（担当者を変更した場合は担当者別ビューの所属グループも移動します）。
- 影響: 実装規模が約 1 日分増え、合計 2〜3 日規模になります。また index.html の稼働中コードを移動するリファクタが入るため、一覧側のモーダル回帰確認をテスト計画に追加しました（9〜11）。
