# 質問票：ガントチャート上のマウス操作で子課題の開始日・期限日を変更する

`docs/改修計画書_ガント子課題ドラッグ日付変更.md` のドラフトに対する確認事項です。各項目に**推奨案**を記載しています。「推奨で可」の一言でも回答になります。
（優先度: ★★★ = 実装前に必須 / ★★ = 実装中に決めれば間に合う / ★ = 将来検討でも可）

## Q1. ドロップしたら即保存するか ★★★

ドラッグで日付を変えたとき、Backlog に保存するタイミングです。

- **推奨: ドロップした時点で即保存**。ドラッグ中は新しい期間（例: `11/18(水) 〜 11/25(水)　6 日`）を表示し、`Esc` で取り消し可能。保存後に「元に戻す」ボタン付きの通知を数秒表示する（Q2）。
- 代案 A: ドロップ後に「11/18〜11/25 に変更しますか？」の確認ダイアログを出す（誤操作に強いが、1 件ごとに 1 クリック増える）。
- 代案 B: 複数の課題を動かしてから「保存」ボタンでまとめて反映する（未保存の変更を管理する UI が必要になり、実装量が大きく増えます）。

→ 推奨案で確定

## Q2. 「元に戻す」機能 ★★

- **推奨: 保存直後の通知に「元に戻す」ボタンを付ける**（直前の 1 件のみ。押すと元の日付で再保存）。
- 代案: 付けない（戻したいときはもう一度ドラッグするか、詳細モーダルで直す）。

→ 推奨案で確定

## Q3. 日付の刻みと、週・月表示での扱い ★★★

ガントの 1 日あたりの幅は、日表示 28 px / 週表示 約 6 px / 月表示 約 2 px です。

- **推奨: すべての表示で 1 日単位に丸めて操作可能**。週・月表示では細かい調整がしにくいため、ドラッグ中の日付表示を見ながら合わせる。
- 代案 A: 週表示では 1 日単位、月表示では**ドラッグ不可**（日・週表示に切り替えて操作）。
- 代案 B: 表示の単位に合わせて丸める（週表示は週単位＝月曜始まり、月表示は月単位）。

→ 推奨案で確定

## Q4. 土日・祝日の扱い ★★

- **推奨: カレンダー日で動かす（土日に置くことも可）**。バーを移動したときも期間の**日数（カレンダー日）**を保ったまま平行移動する。
- 代案 A: 開始日・期限日が土日になる場合は、直近の平日に自動で寄せる。
- 代案 B: 移動時は**営業日数**を保つ（例: 月〜金の 5 営業日の課題を 2 日後ろへずらすと水〜翌火になる）。
  - ※ 祝日はガント画面では判定していません（月別工数の就業カレンダーを使えば対応可能ですが、実装量が増えます）。

→ 推奨案で確定

## Q5. 日付が入っていない子課題に、ドラッグで期間を新規設定するか ★★

現在、開始日・期限日のどちらかが空の子課題はバーが描かれません（既定の「日付未設定を隠す」ON では行自体も出ません）。

- **推奨: 対応する**。「日付未設定を隠す」を OFF にしたときに表示される日付なし子課題の行で、タイムライン上をドラッグした範囲を開始日〜期限日として設定する。
- 代案: 今回は対象外（既存のバーの移動・伸縮のみ。日付なしの課題は詳細モーダルで設定）。

また、開始日だけ・期限日だけが入っている子課題（片方だけ）の扱いはどちらがよいですか？

- **推奨: 「日付なし」と同じく、ドラッグした範囲で両方を設定し直す**。
- 代案: 入っている側の日付を目印として表示し、空いている側だけを設定する。

→ 推奨案で確定（開始日だけ・期限日だけの場合も推奨案で確定）

## Q6. バーをクリックしたときの動作 ★★★

現在、バーをクリックすると **Backlog の課題ページが別タブで開きます**。ドラッグとの区別は「4 px 以上動いたらドラッグ」で行います。

- **推奨: クリック時の動作は現行のまま（Backlog を開く）**。
- 代案: 子課題のバーのクリックは**詳細モーダルを開く**に変更する（件名クリックと同じ。Backlog へは課題キーのリンクから）。ドラッグで日付を変えたあと続けて工数・進捗を直す流れが自然になります。

→ 推奨案で確定

## Q7. 処理済み・完了の子課題も動かせるようにするか ★★

- **推奨: 動かせる**（実績の期間を後から正す用途があるため）。
- 代案: 処理済み・完了（ステータス 3・4）の子課題はドラッグ不可にする（誤って過去の記録を動かすのを防ぐ）。

→ 推奨案で確定

## Q8. 対象のビュー ★★

- **推奨: 「📋 案件別」「👤 担当者別」の両方で有効**。担当者別ビューでは、ドロップ後に担当者行・案件行の集約帯（空き状況）も新しい期間で描き直されます。
- 代案: 案件別ビューのみ／担当者別ビューのみ。

→ 推奨案で確定

## Q9. 保存後に行の並びが変わること ★

担当者別ビュー（子課題は常に開始日順）や、案件別ビューで子課題の並びを「開始日順」にしている場合、開始日を動かすと保存後にその行の位置が変わります。

- **推奨: 仕様とする**（並び順の規則を優先）。
- 代案: 画面を再読み込みするまでは行の位置を固定する（操作直後に行が飛ばないが、並び順が一時的に規則とずれる）。

→ 推奨案で確定

## Q10. 画面端での自動スクロール ★

- **推奨: 対応する**。タイムラインの左右端近くまでドラッグすると、自動で横スクロールして表示範囲外の日付まで動かせる。
- 代案: 対応しない（表示範囲外へ動かしたいときは、いったん途中でドロップしてからスクロールして再度ドラッグ）。

→ 推奨案で確定

## Q11. 編集できる人の制限 ★

BPM には現在ログインの仕組みがなく、詳細モーダルと同様、画面を開ける人は誰でも日付を変更できます。

- **推奨: 現行どおり制限なし**（変更は Backlog の更新履歴に API キーのユーザー名義で残ります）。
- 代案: 「編集モード」トグルを設け、ON のときだけドラッグを有効にする（閲覧中の誤操作を防ぐ目的。権限管理ではありません）。

→ 推奨案で確定

## Q12. スコープ外の確認 ★

以下は今回含めない想定です。問題ないですか？

- 親案件のバーのドラッグ（ご要望どおり子課題に限定）
- 複数の子課題をまとめて選択・移動、先行／後続の関係による連動移動
- 担当者別ビューで別の担当者の行へドロップして担当者を変える操作
- 予定工数の変更、タッチ操作（タブレット・スマートフォン）での動作保証
- 変更時に Backlog へコメントを自動追記すること

→ 問題なし
