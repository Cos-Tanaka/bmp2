# 質問票：ガントチャート 担当者別ビューの改善（改修要望 2・3）

`docs/改修計画書_ガント担当者別ビュー改善.md` のドラフトに対する確認事項です。各項目に**推奨案**を記載しています。「推奨で可」の一言でも回答になります。
（優先度: ★★★ = 実装前に必須 / ★★ = 実装中に決めれば間に合う / ★ = 将来検討でも可）

---

## 要望 2（担当者行の集約帯）について

## Q1. 「帯を 1 本」の意味 ★★★

「担当者の行にスケジュールの帯を 1 本で表示」には 2 通りの解釈があります。

- **A 案（推奨）: 1 レーン（1 行ぶんの高さ）に、作業のある期間だけを塗る**
  
  ```
  👤 山田太郎   ▬▬▬▬▬▬        ▬▬▬▬      ▬▬
                        ↑ここが空き
  ```
  
  課題の谷間が空白として残るので、**空きがそのまま目で分かります**（ご要望の目的に直結）。
- B 案: 最早開始日〜最遅期限日を**1 本の連続バー**で塗る
  
  ```
  👤 山田太郎   ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬
  ```
  
  シンプルですが、**間の空きも塗り潰される**ため「空きの確認」には使えません。

→ A 案でよいですか？

→ A案でOK

## Q2. 週末の扱い（帯を切るか繋ぐか） ★★★

金曜が期限の課題と、翌月曜開始の課題は「間が土日 2 日」空きます。

- **推奨: 間が土日だけなら繋げる**（土日は空きに数えない）。実質的な空きだけが隙間として見える。
- 代案: カレンダー日どおり分断する（土日も隙間として表示される）。

なお**祝日は Backlog から取得できない**ため考慮できません（祝日は隙間として表示されます）。

→ 推奨でOK

## Q3. 帯の色と進捗表示 ★★

- **推奨: 帯に含まれる課題のうち最も悪い健全性の色（🔴 > 🟡 > 🟢）で塗る。進捗の塗り分けはしない**
  （複数課題をまとめた帯に「平均進捗」を出しても解釈が難しいため）
- 代案 1: 進捗を工数で加重平均して塗る
- 代案 2: 健全性を使わず単色（グレー）にして、空きの有無だけを見せる

→ 推奨でOK

## Q4. 多重アサイン（期間の重なり）の表示 ★★

1 レーンに畳むと「同時に 2 件走っている」ことが見えなくなります。

- **推奨: 重なっている区間だけ色を濃くし、ツールチップに「同時 N 件」を表示**
- 代案: 何もしない（重なりは担当者行を開いて子課題行で確認する）

→ 推奨でOK、ただし並列タスクが常態化しているので、見やすく設定をお願いする。

## Q5. 帯を出すタイミング ★★

- **推奨: 常に表示**（担当者行を開いていても、閉じていても帯が出る）
- 代案: 閉じているときだけ表示（開くと子課題行があるので帯は消す）

→ 推奨でOK

## Q6. 空き期間の強調 ★

- **推奨: 何もしない**（帯が無い部分＝空き、として見る）
- 代案: 今日以降の空き期間を薄い色でハイライトする

→ 推奨でOK

## 要望 3（担当者 → 親案件 → 子課題の 3 階層）について

## Q7. 親案件行に出すバー ★★

- **推奨: その担当者ぶんの子課題だけを集約した帯**（他の人が担当している同じ案件の課題は含めない）
  → 「この案件で自分はいつ動くのか」が分かる
- 代案: 案件全体の期間（案件別ビューの親バーと同じもの）

→ 推奨でOK

## Q8. 開閉の既定と「全て開く／全て閉じる」の意味 ★★★

3 階層になるため、開閉の段階が増えます。

- **推奨**:
  - 既定は「担当者=開・親案件=開」（＝現在と同じく子課題まで見えている状態）
  - **▶ 全て閉じる** → 担当者行だけ（親案件行も畳む）＝**空き確認の状態**
  - **▼ 全て開く** → 3 階層すべて展開
- 追加の確認: 中間段階の **「案件まで開く」チップ**（担当者＋親案件行までを表示し、子課題は畳む）は必要ですか？（担当者ごとの案件の掛け持ち状況を俯瞰する用途に有効ですが、チップが 1 つ増えます）

→ 推奨でOK

## Q9. 子課題行の親案件キー併記 ★

親案件行が出るようになると、子課題行の `[ASPIT-100]` 併記は冗長になります。

- **推奨: 削除する**（そのぶん件名に幅を回す）
- 代案: 残す

→ 推奨でOK

## Q10. 担当者内での案件の並び順 ★

- **推奨: その担当者の子課題の最早開始日が早い順**（同日は案件キー順）
- 代案 1: 案件キー順
- 代案 2: 課題件数の多い順

→ 推奨でOK、担当の子課題でスケジュールが空欄は、その中で一番下に案件キー順で表示

## Q11. 担当者行の見出し表示 ★

現在は `👤 山田太郎 [5] 計 40h/32h` です。3 階層化に合わせて `👤 山田太郎  2案件 / 5課題  計 40h/32h` に変更する想定です。

- 確認: この表記でよいですか？（工数合計の表示要否も含めてご指定ください）

→ OK

## 全体について

## Q12. 案件別ビュー（📋）への波及 ★

案件別ビューの親案件行には、既に「子課題から集約した細バー（最早開始〜最遅期限の 1 本）」があります。

- **推奨: 案件別ビューは変更しない**（案件の期間を示すという別の意味があるため）
- 代案: 案件別ビューの親バーも、要望 2 と同じ「作業のある期間だけ塗る」方式に統一する

→ 推奨でOK

## Q13. リリース単位 ★★

改修要望 1（左ペイン幅）・3（3 階層）・2（集約帯）は同じ画面の同じ描画処理を触ります。

- **推奨: 要望 1 → 3 → 2 の順に実装し、まとめて 1 回でリリース**（動作確認が 1 回で済む。合計 2 日前後）
- 代案: 要望 1 を先行リリースし、要望 2・3 を後追いでリリース（先に幅の改善だけ早く使える）

→ 推奨でOK

## Q14. スコープ外の確認 ★

以下は今回含めない想定です。問題ないですか？

- 稼働率（工数 ÷ 期間）の計算・ヒートマップ表示
- 「空きの多い担当者順」などの並べ替え
- 帯のクリックによる課題選択（複数課題を含むため特定できないので、クリックは無効にします）
- バーのドラッグによる日付変更・担当者の付け替え
- バックエンド・API の変更（不要）

→ OK
