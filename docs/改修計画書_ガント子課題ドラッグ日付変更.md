# 改修計画書：ガントチャート上のマウス操作で子課題の開始日・期限日を変更する

- 作成日: 2026-11-17
- 対象: `frontend/html/gantt.html`（バーのドラッグ操作・保存処理）。**バックエンドの変更は不要**（既存の `PATCH /api/issue/<key>` を使う）
- ステータス: **確定版**（2026-11-17 `docs/質問票_ガント子課題ドラッグ日付変更.md` の回答を反映。Q1〜Q11 すべて推奨案を採用、Q12 スコープ外は問題なし。本文中の「（Qn）」は質問票の項目番号）

## 1. 背景・目的

| 要望 | 目的 |
|---|---|
| ガントチャートのスケジュール（右側のタイムライン）上で、**子課題に限り**、マウス操作で開始日・期限日を設定できるようにする | 日程調整のたびに詳細モーダルを開いて日付を打ち直す手間をなくし、前後の課題や担当者の空きを見ながら直感的に予定を組めるようにする |

## 3. 操作仕様（推奨案ベース）

### 3.1 対象

- **子課題のバーのみ**。親案件のバー（自身の日付・子から集約した細いバーとも）と、担当者別ビューの集約帯はドラッグ不可（現状どおり）。
- 案件別ビュー・担当者別ビューの**両方**で有効（Q8）。
- 処理済み・完了の子課題も対象に含める（Q7）。

### 3.2 操作

| 操作 | つかむ位置 | 変わる値 | カーソル |
|---|---|---|---|
| **移動** | バー中央部 | 開始日・期限日を同じ日数だけずらす（期間の日数は維持） | `grab` / `grabbing` |
| **開始日の変更** | バー左端（約 6 px） | 開始日のみ | `ew-resize` |
| **期限日の変更** | バー右端（約 6 px） | 期限日のみ | `ew-resize` |
| **新規に期間を引く** | 日付未設定（開始日だけ・期限日だけの片方のみも含む）の子課題行の空きトラック | ドラッグした範囲で開始日・期限日の両方を設定し直す（Q5） | `crosshair` |

- **スナップ**: 1 日単位（Q3）。週・月粒度でも内部的には日単位で丸める。
- **土日・祝日**: 吸着や自動回避はしない。カレンダー日で動かす（Q4）。
- **制約**: 開始日 > 期限日にはならないよう、端のドラッグは「最短 1 日（開始日 = 期限日）」で止める。親案件の期間からはみ出すことは許す（親に日付が入っていない案件が大半のため）。
- **キャンセル**: ドラッグ中に `Esc` で元の位置に戻し、保存しない。
- **クリックとの区別**: ポインタ押下から **4 px 未満**の移動で離した場合は従来どおりクリック扱い（Q6: 現行どおり Backlog を開く）。4 px 以上動いたらドラッグとして扱い、クリックは発火させない。
- **ドラッグ中の表示**: バーの横（または追従ツールチップ）に `11/18(水) 〜 11/25(水)　6 日` の形で新しい期間を表示する。通常のツールチップはドラッグ中は出さない。

### 3.3 保存

- **ドロップした時点で即保存**（確認ダイアログなし、Q1）。
  - 送るのは**変わった項目だけ**（`{startDate}` / `{dueDate}` / 両方）。値が元と同じなら送らない。
  - 保存中はバーを半透明＋カーソル `progress` にし、二重操作を防ぐ。
  - 成功: `fetchData(true)` で再取得・再描画（バックエンドは局所更新済みなので即時に新しい値が返る）。画面右上の同期表示に「保存しました」を短く出す。
  - 失敗: バーを元の位置に戻し、エラー内容をトーストで表示する。
- **元に戻す**: 保存直後のトーストに「元に戻す」ボタンを付け、押すと元の日付で再度 PATCH する（Q2）。

### 3.4 ドラッグ中の画面更新の抑止

- 60 秒ポーリングや他操作による `renderGantt()` がドラッグ中に走ると、つかんでいるバーの DOM が消える。
- `dragState`（ドラッグ中・保存中フラグ）を持ち、その間に `renderGantt()` が呼ばれたら**実行を保留**し、ドロップ・保存完了後に 1 回だけ描画する。

## 4. 実装方針（`frontend/html/gantt.html`）

### 4.1 座標の逆変換

- `buildAxis()` に `dateAt(x)`（px → 日付、日単位で切り捨て）を追加する。日・週粒度は `axisStart + floor(x / dayW)`、月粒度は列（月）を特定してから月内の日割りで求める。
- 単体で確認しやすいよう純関数として実装し、`xOf(dateAt(x)) <= x < xOf(dateAt(x)) + dayW` が成り立つことを確認する。

### 4.2 バーの HTML

- `barCell()` で `kind === 'child'` のときだけ `class="gbar draggable"` と `data-id` を付け、左右に `<div class="gbar-handle l">` / `<div class="gbar-handle r">` を追加する。インラインの `onclick` はやめ、クリックとドラッグを同じポインタハンドラで振り分ける。
- バー幅が狭い（例: 14 px 未満）場合はハンドルを出さず、移動のみ可能にする（端をつかめないため）。端の変更は粒度を「日」に切り替えて行う。
- 日付未設定の子課題行（`hideUndated` OFF 時のみ表示）のトラックに `data-id` と `class="gtrack empty-child"` を付け、新規作成ドラッグを受ける（Q5）。

### 4.3 ポインタ処理

- `#ganttRows` に `pointerdown` を**1 か所だけ**委譲で登録（行の再描画でハンドラを付け直さない）。
- `pointerdown` で対象（移動 / 左端 / 右端 / 新規）・元の日付・開始 X を記録し `setPointerCapture`。`pointermove` で `dateAt()` から新しい日付を計算し、バーの `left` / `width` だけを直接書き換える（行全体は再描画しない）。
- 左ペイン幅のドラッグ（`startLeftResize`）と同じ pointer capture 方式に揃える。
- タイムラインの左右端付近までドラッグしたら横スクロールを自動で進める（Q10）。

### 4.4 保存処理

- `saveChildDates(id, { start, due }, original)` を新設し、`PATCH /api/issue/<id>` を呼ぶ。詳細モーダルと同じ API・同じペイロード形式。
- 楽観的更新: 送信前に `allData` 内の該当子課題の `start` / `due` を書き換えて描画し、失敗時に `original` に戻す。

### 4.5 その他

- 子課題の並び: 案件別ビューで「開始日順」設定のとき、担当者別ビュー（常に開始日順）では、保存後の再描画で行の位置が変わる。これは仕様とする（Q9）。
- 健全性（バー色）・計画進捗線・担当者別の集約帯・親の集約バーは、再描画で新しい日付から自動的に再計算される（追加実装なし）。
- `index.html`・月別工数（`workload.html`）は `/api/issues` を読み直した時点で新しい日付を反映する（変更不要）。

## 5. スコープ外

- 親案件のバーのドラッグ（要望どおり子課題に限定）
- 複数の子課題をまとめて移動、依存関係（先行・後続）による連動移動
- 予定工数・担当者のドラッグ変更（担当者別ビューで別の担当者の行へドロップする等）
- バックエンドの変更、Backlog へのコメント自動追記

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| 意図しないドラッグで日付が変わる（即保存のため） | 4 px のしきい値、ドラッグ中の日付ラベル表示、`Esc` キャンセル、保存後の「元に戻す」 |
| 月粒度では 1 px ≒ 0.5 日で細かい調整が難しい | 日付ラベルで確認しながら操作できるようにする。（Q3 で全粒度とも操作可能に確定） |
| 他の人が同じ課題を同時に編集 | 後勝ち（詳細モーダルと同じ）。Backlog 側の更新履歴に残る |
| 多数の課題（約 3,200 件）での操作の重さ | ドラッグ中は対象バーの style だけを更新し、行の再描画はドロップ後 1 回に限定 |
